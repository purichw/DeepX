# คู่มือ CMS DeepX

CMS อยู่ที่ `/admin` ใช้แก้เนื้อหาเว็บไซต์ ผลงาน และรายชื่อพันธมิตร โดยแยก
**ฉบับร่างที่บันทึกแล้ว** ออกจาก **เนื้อหาที่เผยแพร่แล้ว** เอกสารนี้อธิบายสัญญา
และขอบเขตของระบบ ส่วนสถานะ deploy และผลทดสอบจริงอยู่ใน [RELEASE.md](RELEASE.md)
รายการความสามารถในคู่มือนี้ไม่ใช่หลักฐานว่าทดสอบผ่านแล้วทั้งหมด

Product Studio ที่ `/studio` ใช้ CMS และ workspace เดียวกัน เลือกหน้า **Product Studio**
เพื่อแก้ 12 หมวดของหน้าใหม่ได้ ปุ่มเผยแพร่เผยแพร่ฉบับร่างทั้งสองหน้าพร้อมกัน
รายละเอียด field-to-consumer, Concept, verified metrics และ approved reviews อยู่ใน
[STUDIO.md](STUDIO.md#cms-workflow-and-field-coverage)

## เข้าใช้งานและแก้เนื้อหา

1. เปิด [deepxworks.com/admin](https://deepxworks.com/admin) แล้วเข้าสู่ระบบด้วยบัญชีที่เจ้าของอนุญาต รองรับอีเมล/รหัสผ่าน
   ที่มีอยู่ หรือขอลิงก์เข้าสู่ระบบทางอีเมลจากหน้าล็อกอิน
2. บัญชีต้องยืนยันอีเมลและอยู่ใน allowlist ที่เปิดใช้งาน การล็อกอินสำเร็จเพียงอย่างเดียว
   ไม่ทำให้บัญชีทั่วไปเป็นผู้ดูแล รายชื่อและอีเมลผู้ดูแลไม่อยู่ใน Git หรือ public API
3. เลือกหมวด แล้วเลือกภาษาไทยหรืออังกฤษเพื่อแก้ข้อความ รายการแสดงชื่อที่อ่านได้
   กดเปิดเพื่อแก้รายละเอียด เพิ่ม นำออก หรือเลื่อนลำดับได้ตามชนิดรายการ
4. กรอกสองภาษาให้ครบในช่องที่บังคับ ตรวจรูป ลิงก์ และเนื้อหาที่อนุญาตให้เผยแพร่
   ระบบตรวจข้อมูลก่อนบันทึก; ข้อความไม่ครบหรือ URL ไม่ปลอดภัยต้องแก้ก่อน
5. กด **บันทึกฉบับร่าง** เพื่อเก็บงานบนเซิร์ฟเวอร์ เว็บไซต์จริงยังใช้เนื้อหาที่เผยแพร่เดิม
   เปิด CMS อีกครั้งเพื่ออ่านร่างที่บันทึกแล้วได้ งานที่ยังไม่บันทึกอยู่เฉพาะหน้าจอปัจจุบัน
6. ใช้ตัวอย่างฉบับร่างตรวจหน้าเว็บไซต์ ตัวอย่างใช้ renderer เดียวกับหน้าบ้านและ
   ใช้ข้อมูลใน editor; การเปิดตัวอย่างไม่ใช่การเผยแพร่
7. เมื่อพร้อม กด **เผยแพร่** ฉบับร่างที่บันทึกแล้วจะเปลี่ยนข้อมูลสาธารณะพร้อมกันทั้งชุด
   เปิดเว็บไซต์จริงและโหลดใหม่เพื่อตรวจภาษา รูป ลำดับ รายละเอียด และลิงก์ที่แก้

ก่อนเผยแพร่ต้องตรวจทั้งภาษาไทยและอังกฤษ โดยเฉพาะหัวเรื่องยาวและข้อความในการ์ดบนมือถือ
ตัวเลขผลลัพธ์ ลูกค้า และโลโก้พันธมิตรต้องมีข้อมูลจริงและได้รับอนุมัติ ไม่ใช้ตัวเลขใน mockup
เป็นหลักฐานทางธุรกิจ

Supabase Auth ใช้ Site URL `https://deepxworks.com` และอนุญาต callback แบบเจาะจงที่
`https://deepxworks.com/admin` โดยคง callback เดิมของ `deepxsolution.com`,
`deepxtech.vercel.app` และ localhost ทั้งสองรูปแบบไว้ระหว่างย้ายโดเมน
CMS สร้าง `emailRedirectTo` จาก `${window.location.origin}/admin` จึงไม่ต้องฝังชื่อโดเมนในโค้ด
ฐานข้อมูลและ Auth API ยังคงใช้โปรเจกต์ `yazamwbukbtetzqmqcpm` เดิม ไม่ต้องสร้างบัญชีใหม่
session ที่เก็บในเบราว์เซอร์ไม่ย้ายข้ามโดเมนอัตโนมัติ ผู้ดูแลต้องเข้าสู่ระบบบนโดเมนใหม่
ห้ามคัดลอก token ข้าม origin; ใช้ลิงก์เข้าสู่ระบบใหม่หรือรหัสผ่านเดิม
สถานะ redirect ของโดเมนเก่าและผลตรวจจริงอยู่ใน [RELEASE.md](RELEASE.md)

## ฉบับร่าง การทำงานหลายหน้าต่าง และประวัติ

CMS มีฉบับร่างร่วมบนเซิร์ฟเวอร์หนึ่งชุด ไม่ใช่สำเนาร่างแยกของผู้ดูแลแต่ละคน
ทุกครั้งที่ข้อมูลเปลี่ยนและบันทึกสำเร็จจะได้ revision ใหม่ พร้อม snapshot และผู้บันทึก
การบันทึกข้อมูลเดิมซ้ำไม่สร้าง revision เพิ่มโดยไม่จำเป็น

ก่อนบันทึกและเผยแพร่ เซิร์ฟเวอร์ตรวจว่า revision ที่หน้าจอถืออยู่ยังเป็นตัวล่าสุด
หากคนอื่นหรืออีกแท็บบันทึกก่อน ระบบปฏิเสธการเขียนทับ งานที่พิมพ์อยู่คงอยู่ให้ตรวจ
ใช้ **ดาวน์โหลดฉบับทำงาน** เก็บสำเนาก่อนยืนยันโหลดฉบับล่าสุด แล้วรวมการแก้ไขใหม่
สำเนาที่ดาวน์โหลดเป็น JSON สำหรับกู้ข้อมูล ไม่ใช่ขั้นตอนแก้เนื้อหาปกติและไม่มีการ import
หรือรวมข้อมูลอัตโนมัติ

การเผยแพร่เป็นธุรกรรมเดียว: เนื้อหาทุกหมวด ผลงาน ลำดับ และพันธมิตรเปลี่ยนพร้อมกัน
เมื่อขั้นตอนใดล้มเหลว ข้อมูลเผยแพร่เดิมต้องไม่เปลี่ยนบางส่วน ประวัติการบันทึกและการเผยแพร่
เก็บแยกจากข้อมูลสาธารณะและอ้างอิงตัวตนที่เซิร์ฟเวอร์ยืนยัน
มี snapshot สำหรับตรวจสอบ แต่เวอร์ชันนี้ยังไม่มีปุ่มคืน revision เก่าอัตโนมัติ

## แก้อะไรได้บ้าง

ชื่อเทคนิคในตารางใช้ให้ผู้พัฒนาตรวจ coverage; ผู้ดูแลทำงานผ่านชื่อหมวดและช่องกรอกใน CMS
ฟิลด์ข้อความสองภาษาต้องมีค่า `th` และ `en` ชุดหัวข้อร่วมประกอบด้วยข้อความเหนือหัวเรื่อง
(`eyebrow`), หัวเรื่อง (`title`) และคำอธิบาย (`description`) ที่บางตำแหน่งรองรับ
ชุดรายการร่วมมีรหัสถาวร (`id`, อ่านอย่างเดียว), ไอคอน (`icon`), หัวเรื่อง, คำอธิบาย
และรายละเอียด (`detail`) รายการแก้ เพิ่ม นำออก และเรียงใหม่ได้; ส่วนที่บังคับรายการ

### ขอบเขตที่ต้องแยกจากช่องแก้ไข

ชุด schema มีฟิลด์ร่วมเผื่อ renderer หลายแบบ จึงไม่ใช่ทุกฟิลด์มีผลในทุกตำแหน่ง
ฟิลด์ที่ไม่มี consumer ถูกซ่อนจาก editor โดยคงค่าเดิมในเอกสาร ได้แก่
`hero.description`, `industries.description`, `industries.items[].icon`,
`process.items[].icon`, `applications.items[].icon`, `why.items[].description`,
`partners.eyebrow/description`, `contact.description`, `insights.eyebrow/description`,
`privacy.eyebrow/description`, `ui.viewAll` และ `ui.back` การเพิ่ม consumer ให้ฟิลด์เหล่านี้
ต้องปรับตารางและหลักฐานการทดสอบพร้อมกัน

ฟิลด์ `description` ในชุดหัวข้อเป็น optional เวอร์ชันนี้แก้ได้เมื่อมีค่าอยู่ในเอกสารและ
ตำแหน่งนั้นมี consumer; ยังไม่มีช่องเพิ่มคำอธิบาย optional ที่ไม่เคยมีมาก่อน

โครงหน้า ลำดับ section หลัก การวางปุ่ม สี ฟอนต์ ภาพ Neural X, favicon, routes,
ชนิดไอคอนที่รองรับ และพฤติกรรม dialog อยู่ในโค้ด CMS นี้เป็น structured content editor
ไม่ใช่ page builder อิสระ เมนูเป็นรายการชั้นเดียว ไม่มี parent/child หรือ visibility toggle
แยกจากการนำรายการออก ผลงานและพันธมิตรเผยแพร่พร้อมฉบับร่างทั้งชุด ไม่มีสถานะ
draft/published แยกของแต่ละรายการใน editor และตัวอย่างเป็นหน้าเต็มสำหรับตรวจงาน
ไม่ใช่ canvas ที่พิมพ์แก้ได้โดยตรง

## รูปแบบฟอร์มร่วม

ทุกหมวดและรายการย่อยใช้ `EditorFields` กับ `cms.css` ร่วมกัน เมื่อพื้นที่ฟอร์ม
กว้างอย่างน้อย 560px ชื่อฟิลด์อยู่ทางซ้ายและช่องกรอกอยู่ทางขวา; พื้นที่แคบใช้ชื่อ
เหนือช่องแบบชิดซ้าย ข้อความอีกภาษาและคำแนะนำอยู่ใต้ช่องที่เกี่ยวข้องเสมอ
การจัดแนวนี้เป็นข้อกำหนดเฉพาะ Content Studio ไม่เปลี่ยนหน้าบ้าน

ข้อความสั้นเริ่มหนึ่งบรรทัด ส่วนเนื้อหา/รายละเอียดเริ่มสามบรรทัดและขยายตามข้อความ
ได้ถึง 320px จากนั้นเลื่อนภายในได้ ยังคงเป็น textarea เดิมเพื่อรักษาการขึ้นบรรทัดใหม่
และตำแหน่งพิมพ์ รูปและวิดีโอใช้ตัวอย่างขนาดกระชับข้าง URL/ปุ่มเมื่อพื้นที่พอ
มือถือคงตัวอักษรในช่อง 16px และความสูง control อย่างน้อย 44px
การปรับความหนาแน่นไม่เปลี่ยน schema, ค่าเนื้อหา, upload, draft หรือ publish

## รูปภาพ วิดีโอ และการล้างค่า

- อัปโหลด JPEG, PNG หรือ WebP ได้ไม่เกิน 5 MiB ต่อไฟล์ หรือใช้ URL ภาพ HTTPS
  และไฟล์เริ่มต้นใต้ `/images/` ช่องรูปแสดงตัวอย่างพร้อมข้อผิดพลาดเมื่อโหลดไม่ได้
  รวมภาพปกวิดีโอ; รูปเก็บใน bucket `cms-media`
- ส่วนเปิดหน้ามีช่องวิดีโอ MP4 ไม่เกิน 30 MiB และภาพปกแยกกัน อัปโหลดผ่านปุ่ม
  หรือกรอก URL HTTPS; วิดีโอในโปรเจกต์ใช้ `/videos/*.mp4` ได้ วิดีโอเก็บใน
  bucket `cms-video` ซึ่งแยกจากรูป ผู้ดูแลที่ผ่าน allowlist เท่านั้นจึงอัปโหลดได้
- ไฟล์ที่อัปโหลดมี URL สาธารณะทันที แม้ยังไม่ได้เผยแพร่เนื้อหา ใช้เฉพาะสื่อที่มีสิทธิ์เผยแพร่
  และไม่ใส่เอกสารภายในหรือข้อมูลส่วนตัวในทั้งสอง bucket
- เปลี่ยนรูปหรือวิดีโอด้วยการอัปโหลดไฟล์ใหม่ ระบบสร้าง path ใหม่และไม่เขียนทับไฟล์เก่า
  การล้าง reference ไม่ลบไฟล์จาก Storage จึงไม่ทำให้หน้าที่อ้างไฟล์เดิมเสีย
- วิดีโอ Hero เป็นพื้นหลังเต็ม Banner บนเดสก์ท็อป/แท็บเล็ต โดยครอบภาพให้เต็มพื้นที่
  และมีไล่เฉดมืดหลังข้อความ บนมือถือไม่เกิน 600px ยังคงเป็นพื้นหลังภายใน Banner
  หลังข้อความและปุ่ม โดยครอบพื้นที่ว่างซ้าย–ขวาของเฟรม 16:9 ให้โลโก้/ชื่อ DeepX
  อยู่ภายในจอ ไม่ย้ายวิดีโอไปไว้ท้าย Banner และไล่ขอบให้กลืนกับพื้นหลัง
  เล่นอัตโนมัติแบบปิดเสียงและวนซ้ำ ไม่มีปุ่ม Play
  และหยุดเมื่อพ้นจอหรือซ่อนแท็บ
  ผู้ใช้ที่ตั้งลดการเคลื่อนไหวจะเห็นภาพปก/ภาพนิ่ง ล้าง `videoUrl` แล้วบันทึกและเผยแพร่
  เพื่อกลับไปใช้ Neural X เดิม; ล้าง `videoPoster` ได้โดยไม่ลบวิดีโอ
  ควรใช้ MP4 H.264 แนวนอนพร้อมภาพปก และตรวจการเล่นจริงในตัวอย่างก่อนเผยแพร่
  ระบบใช้วิดีโอหนึ่ง URL ทุกขนาดจอ ยังไม่เลือกไฟล์มือถืออัตโนมัติ
- ภาพอุตสาหกรรมมีข้อความอธิบายสองภาษาและจุดโฟกัสแนวนอน/แนวตั้ง 0–100%
  จุดโฟกัสควบคุมตำแหน่งการครอบในกรอบการ์ด ไม่แก้ต้นฉบับไฟล์
- ล้าง email, website หรือ LinkedIn เพื่อซ่อนช่องทางนั้น LINE แสดงเมื่อมีทั้งชื่อบัญชี
  และลิงก์; ล้างค่าใดค่าหนึ่งแล้วลิงก์ LINE ต้องหายทุกตำแหน่งหลังเผยแพร่
- ช่องข้อความสองภาษาที่บังคับไม่รับค่าว่าง รูปโลโก้พันธมิตรเป็นข้อมูลบังคับของรายการ
  ถ้ายังไม่มีโลโก้ที่อนุมัติ ให้เก็บงานไว้ก่อนเพิ่มรายการนั้น ไม่ใช้โลโก้สมมติ

## แหล่งข้อมูลและความสดใหม่

Published Supabase records เป็นแหล่งจริงของหน้าบ้าน CMS draft เป็นงานที่ยังไม่เผยแพร่
และ seed JSON เป็นเพียงข้อมูลเริ่มต้น/fixture การ deploy ห้ามนำ seed มาทับเนื้อหาที่แก้แล้ว
เมื่ออ่านฐานข้อมูลไม่ได้ เว็บไซต์แสดงข้อผิดพลาดพร้อมให้ลองใหม่ ไม่แทนที่ด้วยข้อความเก่า

เนื้อหาในหน้าอ่านใหม่เมื่อผู้ใช้โหลดเว็บไซต์ ส่วน HTML title/description และ social metadata
ถูกสร้างตอน build การแก้ SEO ใน CMS จึงต้อง build/deploy ใหม่เพื่อให้ crawler ที่อ่าน HTML
ได้ค่าใหม่ ไม่มีการสั่ง deploy อัตโนมัติจากปุ่มเผยแพร่ และหน้าเว็บที่เปิดค้างไม่อัปเดตแบบ realtime

SEO ใช้ชื่อแบรนด์, title/description, อีเมลและ LinkedIn จากหมวดเว็บไซต์เพื่อสร้าง
Open Graph/Twitter และข้อมูล `Organization`/`WebSite`; ภาพ social ใช้ภาพปก Hero
ที่ตั้งไว้ การล้างภาพปก/อีเมล/LinkedIn จะไม่เติมค่าเก่ากลับ Canonical, sitemap และ
Google verification เป็นการตั้งค่าระบบ แยกจากลิงก์เว็บไซต์ในช่องทางติดต่อ
ดูรายละเอียดและขั้นตอน Search Console ใน [SEO.md](SEO.md)

## สิ่งที่นำมาจากแนวทาง Mongkol Wela

นำหลัก owner เดียวต่อฟิลด์, save/reopen/public read-back, การล้างค่าที่ไม่ฟื้น seed,
สิทธิ์ฝั่งเซิร์ฟเวอร์, revision conflict, การแยก draft/live และการตรวจ consumer จริงมาใช้
DeepX ใช้ server draft ของตนเองและ shared renderer สำหรับตัวอย่าง จึงไม่เรียก
browser-local draft ว่าเป็นการทำงานร่วมกัน และไม่เรียกการเปิดเว็บจริงว่าตัวอย่างร่าง

ไม่นำกิจกรรม แผนที่ ดูดวง ร้านค้า สมาชิก หรือ analytics จากต้นแบบมาเพิ่มโดยอัตโนมัติ
เวอร์ชันนี้ยังไม่มี approval หลายระดับ, scheduled publishing, role management ใน UI,
revision restore, full media library, bulk edit, rich-text/page builder หรือ dashboard
สถิติธุรกิจ ห้ามแสดงปุ่มหรือผลสำเร็จของความสามารถเหล่านี้จนมี backend และทดสอบจริง

## เกณฑ์ตรวจเมื่อเปลี่ยน CMS

ตรวจช่องที่แก้ผ่าน editor จริง → บันทึก → เปิดใหม่ → ตัวอย่าง → เผยแพร่ → public API
และตำแหน่งบนเว็บที่ใช้ค่านั้น รวมกรณีล้างค่า/นำออก/เรียงใหม่ตามความเสี่ยงของงาน
ตรวจบัญชีไม่มีสิทธิ์ ข้อมูลไม่ครบ revision เก่า และการอัปโหลดผิดชนิดด้วย

`supabase/tests/cms_access.sql` เป็นการตรวจสิทธิ์และธุรกรรมด้วย fixture ที่ rollback
ไม่แทนการพิสูจน์ login หรือการใช้งานผ่านเบราว์เซอร์ บันทึกผลจริง ภาพของ revision
ปัจจุบัน และข้อจำกัดที่ยังไม่ได้ตรวจใน [RELEASE.md](RELEASE.md)
